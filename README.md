# ربات زمان‌بند پست تلگرام

این ربات جایگزین قابلیت زمان‌بندی خودِ تلگرام است. شما پست‌ها (متن/عکس/ویدیو) را برای ربات
می‌فرستید و ربات بر اساس بازه‌های زمانی‌ای که تعریف کرده‌اید، خودش سر وقت در کانال یا گروه منتشر می‌کند.
چون منطق زمان‌بندی و ارسال هر ۶۰ ثانیه از دیتابیس بازخوانی می‌شود، در برابر ری‌استارت شدن سرویس روی
Railway مقاوم است (برخلاف "Schedule" خودِ تلگرام که گاهی گیر می‌کند).

## امکانات

- کار روی چند کانال/گروه هم‌زمان، هرکدام با تنظیمات جدا (بازه‌های زمانی و صفِ پستِ مستقل).
- تعریف چند بازه زمانی برای هر چت (مثلاً ۱۲:۰۰ تا ۲۴:۰۰ هر ۳ ساعت، و ۰۰:۰۰ تا ۰۸:۰۰ هر ۴ ساعت).
- ارسال پست به ربات با فوروارد یا ارسال مستقیم متن/عکس/ویدیو.
- تخصیص خودکار پست‌های صف به اولین اسلات زمانی خالی.
- مدیریت کامل از طریق چت خصوصی با ربات (بدون نیاز به پنل وب).

## پیش‌نیاز: ساخت ربات در بات‌فادر

۱. در تلگرام به [@BotFather](https://t.me/BotFather) پیام دهید.
۲. `/newbot` را بزنید و یک نام و یوزرنیم انتخاب کنید.
۳. توکنی که می‌دهد را کپی کنید (چیزی شبیه `123456:ABC-DEF...`) — همین می‌شود `BOT_TOKEN`.

## استقرار روی Railway از طریق GitHub

۱. یک ریپازیتوری جدید در گیت‌هاب بسازید و تمام فایل‌های این پروژه را در آن push کنید:
   ```bash
   git init
   git add .
   git commit -m "initial commit"
   git branch -M main
   git remote add origin https://github.com/USERNAME/REPO.git
   git push -u origin main
   ```
۲. در [Railway](https://railway.app) وارد شوید و **New Project → Deploy from GitHub repo** را بزنید
   و همین ریپازیتوری را انتخاب کنید.
۳. به تب **Variables** بروید و متغیرهای زیر را اضافه کنید:
   - `BOT_TOKEN` = توکنی که از بات‌فادر گرفتید
   - `TIMEZONE` = `Asia/Tehran` (اختیاری، پیش‌فرض همین است)
   - `DB_PATH` = `/data/bot.db`
۴. **خیلی مهم — پایدارسازی دیتابیس:** روی Railway فایل‌سیستم بدون Volume با هر دیپلوی مجدد پاک می‌شود.
   از تب **Settings → Volumes** یک Volume جدید بسازید و آن را روی مسیر `/data` مونت کنید. اگر این کار را
   نکنید، با هر ری‌استارت/دیپلوی، صف پست‌ها و بازه‌های زمانی از بین می‌رود.
5. چون این یک ربات polling است نه یک وب‌سرویس، لازم نیست پورتی باز شود؛ اگر Railway هلث‌چک HTTP فعال
   داشت، از تب Settings آن را غیرفعال کنید تا سرویس را به‌اشتباه "ناسالم" تشخیص ندهد.
۶. دیپلوی را بزنید. با گرفتن لاگ‌ها باید خط `Bot starting (polling)...` را ببینید.

> نکته: با هر پوش جدید به شاخه `main` در گیت‌هاب، Railway به‌صورت خودکار دوباره دیپلوی می‌کند.

## اجرای محلی برای تست

```bash
python -m venv venv
source venv/bin/activate   # ویندوز: venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env   # و BOT_TOKEN را داخلش بگذارید
export $(cat .env | xargs)   # یا از پکیج python-dotenv استفاده کنید
python main.py
```

## نحوه استفاده در تلگرام

۱. با اکانت تلگرام خودتان، به ربات پیام دهید و `/start` را بزنید (این مرحله را حتماً **قبل یا بعد** از
   مرحله بعد انجام دهید؛ ترتیب مهم نیست، اما برای اینکه ربات بتواند به شما پیام خصوصی بدهد باید حتماً
   یک‌بار در پیوی با آن `/start` زده باشید).
۲. ربات را در کانال یا گروه موردنظر **ادمین** کنید (دسترسی ارسال پیام کافی است).
۳. در پیوی ربات دستور `/addwindow` را بزنید:
   - کانال/گروه موردنظر را از لیست انتخاب کنید.
   - ساعت شروع را وارد کنید، مثلاً `12:00`
   - ساعت پایان را وارد کنید، مثلاً `24:00`
   - فاصله بین پست‌ها را به ساعت وارد کنید، مثلاً `3`
   - اگر بازه دوم هم می‌خواهید (مثلاً `00:00` تا `08:00` هر ۴ ساعت)، دوباره `/addwindow` را بزنید.
۴. حالا به‌سادگی ۱۰ پست خود را یکی‌یکی برای ربات در پیوی بفرستید یا فوروارد کنید (متن، عکس یا ویدیو).
   اگر بیش از یک کانال دارید، ربات هر بار می‌پرسد این پست برای کدام است.
۵. با `/queue` صف هر کانال و زمان دقیق انتشار هر پست را ببینید؛ با دکمه ❌ می‌توانید هرکدام را لغو کنید.
۶. با `/windows` (یا دکمه «🗓 بازه‌های من») بازه‌های تعریف‌شده هر چت را جدا از بقیه ببینید؛ کنار هر بازه
   دو دکمه هست: ✏️ ویرایش (تغییر ساعت شروع/پایان/فاصله بدون نیاز به حذف و ساخت دوباره) و 🗑 حذف.
۷. با دکمه «📢 کانال‌های من» روی هر کانال/گروه بزنید تا داشبورد مخصوص همان چت باز شود: بازه‌های آن،
   افزودن بازه جدید، صف پست‌های همان چت، و «تنظیم به‌عنوان مقصد پیش‌فرض ارسال». اگر مقصد پیش‌فرض یک چت
   را تنظیم کنید، از آن پس هر پستی که در پیوی برای ربات بفرستید، بدون سؤالِ «برای کدام کانال؟» مستقیم
   به صفِ همان چت اضافه می‌شود — این کار وقتی چند کانال/گروه دارید احتمال اشتباهی رفتن پست را از بین می‌برد.

## نحوه کار زمان‌بندی

هر ۶۰ ثانیه (قابل تنظیم با `TICK_SECONDS`) ربات:
1. برای هر کانال فعال، بر اساس بازه‌های تعریف‌شده، اسلات‌های زمانی آینده (امروز تا ۲ روز بعد) را می‌سازد.
2. پست‌های در صفِ «pending» را به ترتیب ارسال، به اولین اسلاتِ خالی نسبت می‌دهد (وضعیت آن‌ها
   می‌شود «scheduled»).
3. هر پستی که زمانِ زمان‌بندی‌شده‌اش رسیده باشد را همان لحظه ارسال می‌کند.

چون این محاسبه هر بار از روی دیتابیس انجام می‌شود، ری‌استارت شدن سرویس (که مشکل رایج Schedule خود
تلگرام است) هیچ پستی را گم نمی‌کند.

## ساختار پروژه

```
scheduler-bot/
├── main.py            # نقطه ورود، ثبت هندلرها
├── db.py              # لایه دیتابیس (SQLite/aiosqlite)
├── scheduling.py       # منطق تولید اسلات زمانی و ارسال
├── handlers/
│   ├── common.py       # /start /help /mychats
│   ├── membership.py   # تشخیص ادمین شدن ربات در چت
│   ├── windows.py      # /addwindow /windows
│   └── posts.py        # دریافت پست و /queue
├── requirements.txt
├── Procfile
├── runtime.txt
└── .env.example
```

## محدودیت‌ها و نکات

- تلگرام اجازه نمی‌دهد رباتی به کاربری که هرگز با آن پیوی نزده پیام بدهد؛ برای همین باید حتماً یک‌بار
  `/start` را در پیوی ربات بزنید.
- اگر پست کانالی fail شود (مثلاً ربات دسترسی ارسال پیام را از دست داده)، وضعیتش `failed` می‌شود؛ فعلاً
  دستور retry جداگانه ندارد — می‌توانید همان محتوا را دوباره برای ربات بفرستید.
- زمان‌بندی بر اساس یک تایم‌زون سراسری (`TIMEZONE`) کار می‌کند، نه جداگانه برای هر کانال.
